# 个人网站架构审查与维护设计

审查日期：2026-11-07。源码：GitHub 官方 HEAD 压缩包，提交 `171110382458a681ce8467e0a625e528e7f6d038`。Git 主站连接超时，本目录是源码快照，不是包含远端历史的 Git 克隆。

## 审查结论

1. **个人资料有多个维护入口。** `_config.yml`、首页、CV 重复姓名、现职、邮箱和学术链接。旧 `_data/cv.json` 甚至仍是模板人物。资料和技术配置应分离。
2. **隐藏导航没有停止发布。** 示例博客、教学、演讲、演讲地图、模板说明页面仍在源码中，部分会进入站点和 sitemap。删除确定的示例内容，保留真实经历、论文摘要和图片。
3. **论文有真实内容，但模板元数据没有清理完。** 五篇论文沿用 `paper-title-number` 文件名；三篇期刊字段分别为 `Journal 1`、`Journal 15`、`September 25`。按同一文件的引用修正，不把真实论文当示例删除。
4. **简历与论文重复。** 用 `selected: true` 标记代表作，让两处共用 collection。CV 独有的中文论文也迁入 collection，不丢失。
5. **技术负担超出展示需求。** 原主题带有评论服务、jQuery 打包、图表支持、地图爬虫、Notebook 生成器、JSON 简历转换器、大量图标字体和 Sass 框架。个人信息展示不需要这些。
6. **域名不一致。** `CNAME` 是 `suyixin.site`，`_config.yml` 却使用 GitHub 域名。统一 canonical、sitemap 和站内资源地址；本次不修改 DNS。
7. **缺少发布前检查。** 唯一 workflow 是会提交代码的地图抓取任务。改为内容检查及 Jekyll 构建检查；沿用 GitHub Pages 分支发布，不变更远端 Pages 设置。

## 方案比较

- **推荐：精简 Jekyll。** 沿用 Markdown、Liquid、GitHub Pages，使用少量本地模板和普通 CSS。
- 只删示例、保留整个主题：视觉变化最小，但大量主题分支、打包器和模板仍需理解。
- 迁移框架或增加 CMS：新增迁移、依赖和部署维护成本，当前没有必要。

## 目标结构

- `_data/profile.yml`：姓名、学位、现职、中英文现职介绍、邮箱、头像、外链、微信图片和资料核对日期；首页、侧栏、CV、联系页、SEO 共用。
- `_pages/*.md`：首页长文、详细简历、联系页等；继续使用 Markdown，不把所有文字拆成配置字段。
- `_publications/*.md`：一篇一文件，元数据和中英文摘要在一起；论文列表自动排序，CV 自动读取代表作。
- `_data/navigation.yml`：主导航；`_config.yml`：只放构建、域名、collection 与插件配置。
- `_layouts/`、`_includes/`：展示逻辑；`assets/css/site.css`：响应式布局、系统深色模式和打印样式，无 npm 构建。
- `scripts/check_content.py`：检查字段、日期、URL、重复路由、缺失图片和导航目标；`scripts/check_site.py`：检查实际构建产物内部链接及资源。

保留现有中英文真实信息，不臆造新的经历、论文日期、DOI 或职称译名。原来的 Chief Engineer / 高级工程师中英文表述原样保留，需本人以后核对。历史研究条目的“至今”也不替换为推测日期。
